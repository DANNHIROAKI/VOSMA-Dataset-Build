# 真实数据集的构建与使用说明

本实验采用 DocLayNet、MOT20、COCO 2017 ↔ Sama-COCO 和 Microsoft ↔ Google Open Buildings V3（肯尼亚）四组真实数据，分别代表文档重复标注、人工标注与检测结果对照、对象标注版本对照和跨来源建筑记录对照。四组数据分别在 Hugging Face 发布，但采用一致的输入形态：**两侧矩形关系 $R_1,R_2$、语义分组信息，以及必要的来源与版本说明**。

本文规定构建与使用口径，不表示数据已经完成构建或上传。发布时应补充实际统计、下载地址和固定版本标识。这里的“构建完成”指原始标注已经完成配对、筛选和几何准备；**不包含 VOSMA 的算法索引或预计算采样结构**，算法自身的预处理仍计入实验成本。

四组主版本均采用单位记录权，使 VOSMA-Area 与 VOSMA-IoU 使用完全相同的输入，只改变采样权重。记 $I(r,s)$ 为交集面积，$A_r,A_s$ 为两个矩形的面积，则

$$
w_{\mathrm{Area}}(r,s)=I(r,s),\qquad
w_{\mathrm{IoU}}(r,s)=\frac{I(r,s)}{A_r+A_s-I(r,s)}.
$$

总质量为正时，两种算法分别按对应权重进行独立同分布、有放回采样。样本是**矩形记录对**，不是预先确认的一对一对象匹配。零交叠关系没有采样概率，因此这些实验属于加权候选关系核验，而不是全面的漏标、误检或异常发现。

## 1. DocLayNet：人工版面框与固定模型预测框

### 1.1 数据集简要介绍

DocLayNet 是文档版面分析数据集，包含 80,863 个页面，覆盖金融报告、科学论文、法律法规、政府招标文件、手册和专利等领域。其 11 个版面类别包括正文、标题、表格、图片、列表和页眉页脚等，标注对象是页面中的矩形版面区域。[^doclaynet]

本实验采用原始人工版面标注作为参考侧，并在同一批页面上运行一个固定版面检测模型，生成预测侧。**本节不再采用重复人工标注方案，也不依赖 `precedence=1` 或 `precedence=2` 提取第二套框。** 所用页面清单与原始划分在构建时固定，实际页面数与框数以构建结果为准，不引用重复标注页数作为实验规模。

### 1.2 研究中的使用方式与实际意义

**实验单位是同一物理页面。** 两侧关系定义为：

$$
\begin{aligned}
R_1 &= \text{同一页面的 DocLayNet 有效人工版面框},\\
R_2 &= \text{固定版面检测模型在该页面上输出并按固定规则保留的有效预测框}.
\end{aligned}
$$

对应任务是**文档版面检测结果的抽样核验**，而不是人工标注之间的一致性核验。预测框在一次性数据构建阶段生成，不视为 DocLayNet 已经提供的官方检测结果。

主版本不限制两侧类别相同。人工类别与预测类别不一致本身就是值得核验的关系，不能在输入阶段将其删除。类别信息保留为元数据，并记录模型类别与版面类别的对应关系；两侧均采用单位记录权，预测置信度不作为 Area 的额外权重。预测侧的置信度筛选与模型后处理规则在构建前固定，并随发布版本记录。

**VOSMA-Area 的意义：页面空间占比导向的核验。** 人工框与预测框共同占据较大页面区域时，对应关系获得更多抽样机会，可用于检查较大版面区域的类别解释和分块关系。这里的面积是渲染页面坐标下的矩形交叠面积，不是原始纸张的物理面积，也不是检测准确率或文字内容的重要性。

**VOSMA-IoU 的意义：区域几何一致性导向的核验。** 相对重合度较高的人工框—预测框关系更容易被抽到，可用于核验位置、尺度和区域边界较一致的候选对应。它偏向几何相似关系，而不是专门优先寻找边界差异最大的区域；采样结果也不等于已确认的一对一匹配。

版面区域本身就是任务对象，因此两种算法分别提供页面空间占比和相对定位一致性两个审查视角。本实验用于评价采样算法，不据此证明检测模型的独立测试泛化能力；模型训练数据与所选页面的重叠情况应另行核查，不能仅因使用原始验证或测试划分就推定不存在重叠。

### 1.3 构建的基本方法与流程

整体流程为：**固定人工标注、页面清单与检测模型 → 一次性生成预测框 → 按页面配对并还原坐标 → 统一几何表示 → 隔离不同页面 → 核验并发布**。

页面身份结合文档类别、来源集合、文档名和页号确认，同时核对图像身份与尺寸。人工框与模型输入使用同一官方页面 PNG；若推理涉及缩放、填充或其他坐标变换，应将预测框还原到该 PNG 的坐标系，再与人工框组成两侧关系，不混用模型输入坐标或 PDF 坐标。[^doclaynet]

构建时固定模型名称、权重版本、推理实现、图像预处理、置信度筛选与后处理规则，并保留来源和校验信息。预测输出独立于 GT 生成，不能依据 GT 选择、修正或对齐预测框。模型自身的后处理属于已记录的预测生成过程；取得固定输出后，不再额外执行 NMS、去重或基于 GT 的筛选。模型推理失败与正常推理但没有保留框的页面应分别记录，不能把失败伪装成空预测。

**三组数据共用以下几何处理约定。** 从源图像像素坐标计算矩形端点，采用公共尺度 $Q=1000$，将端点乘以 $Q$ 后按最近整数舍入，恰好居中时取偶数，得到半开矩形 $[x_0,x_1)\times[y_0,y_1)$。先求原始右下端点再舍入，不分别舍入宽高后相加；不对各图像单独归一化或缩放。

仅排除非有限坐标、非正宽高及量化后退化的框，并记录数量。默认不裁剪出界框，合法负坐标也予以保留。保留来源记录不同但几何相同的矩形，不额外做匹配、几何去重、NMS 或按 IoU 阈值筛选，也不因某个框没有交叠对象就提前删除它。精确采样的对象是**发布后的定点矩形**，并不表示原始小数坐标的转换无损。

为形成一个可直接输入二维算法的实例，将每页两侧框共同平移到彼此分离的平面区域。区域间距依据实际框范围确定，使组内交集面积与 IoU 保持不变，跨页交集为零。这是语义分组的几何编码，不是重新生成或扰动真实框。

发布前核对所选页面数、成功推理与配对页数、两侧有效框数、置信度筛选数量、无效与空侧情况，并抽查页面叠框、坐标还原及组内交叠关系。所有失败与筛选均留有统计，不用全数据集规模替代实际构建规模。

### 1.4 构建后数据集的形态与使用

Hugging Face 上的主版本是**已经完成预测生成与几何处理的双关系矩形数据集**。每个语义分组对应一个物理页面，左侧是人工版面框，右侧是固定模型预测框，包含两侧记录身份以及回溯页面、人工标注和模型输出所需的信息。运行输入提供统一的整数端点与单位权重，辅助信息保留类别、预测分数、原始分组、局部坐标及平移关系。

三组统一发布可直接加载的 NumPy 矩形数组和少量可追溯元数据，使用相同的列含义与分组约定。运行不依赖下载原始页面图像、模型权重或推理环境；发布内容不包含预先枚举的相交框对、对象匹配或算法索引。

使用时固定发布版本，直接加载 $R_1,R_2$，交给两种算法各自执行预处理与采样，**无须再次运行检测模型，也无须重新处理原始标注**。既可选取完整页面开展小规模验证，也可将所有已隔离页面作为一个全量实例；**每页等量采样后合并，不等于全局按质量采样**。空侧或零总质量实例保留其状态，用于边界情况检查，不伪造有效样本。

原始数据与模型来源、许可、页面范围、构建规则、版本与校验信息随数据保留。模型或推理规则发生变化时，应生成新的数据版本，不覆盖原有实验输入。模型推理属于一次性数据制备，不属于 VOSMA 的运行预处理；算法自身的索引与采样结构仍须在实验中构建并计时。运行时仍须检查面积及累计质量等中间量的数值范围，不能仅凭整数坐标可存储就认定所有计算均不会溢出。

## 2. MOT20：行人 GT 与官方检测结果

### 2.1 数据集简要介绍

MOT20 是面向拥挤场景的多目标行人跟踪基准，共有八个序列。本实验使用公开人工标注的四个训练序列，共 8,931 帧，以及官方提供的 Faster R-CNN 检测结果，不使用缺少公开 GT 的测试部分。[^mot20]

原始任务研究行人的检测与跨帧跟踪；本实验只使用同帧的两套矩形框，不研究轨迹关联。拥挤画面使同一帧中可能存在较丰富的框交叠关系，但实际连接规模仍须统计，不能仅凭“拥挤场景”推定。

### 2.2 研究中的使用方式与实际意义

**实验单位是“序列名＋帧号”。** $R_1$ 保留有效标志为 `1`、类别为 `Pedestrian`（类别 ID 为 `1`）的人工 GT 框；$R_2$ 保留官方检测结果中几何有效且分数有限的框。[^mot20]

主版本采用“保留全部符合上述条件的官方检测”这一固定口径，不额外设置置信度阈值，不按可见度删除 GT，也不将检测置信度作为 Area 的记录权。两侧权重均为单位权，保证 Area 与 IoU 的输入一致。

**VOSMA-Area 的意义：绝对空间交叠导向的候选审查。** 人工框与检测框交集越大，候选关系获得的抽样机会越多，适用于按图像空间交叠贡献分配核验预算。它天然偏向较大共同矩形范围，不等于检测准确率或去重后的行人覆盖面积。

**VOSMA-IoU 的意义：相对定位一致性导向的候选审查。** 相对重合度较高的 GT—检测框关系更容易被抽到，可用于核验位置与尺度较一致的候选对应。但拥挤场景中不同人的框也可能相交，因此样本不能直接视为同一行人的匹配。

MOT20 在本研究中还承担拥挤关系下的性能实验。官方检测器使用过这些训练序列，因此结果用于评价采样算法，而不是证明检测器的独立测试泛化能力。[^mot20]

### 2.3 构建的基本方法与流程

整体流程为：**固定官方训练数据与检测输出 → 按序列和帧配对 → 筛选两侧记录 → 统一几何表示 → 隔离不同帧 → 核验并发布**。

首先依据序列信息确认帧范围和图像尺寸，然后在同一帧内分别整理 GT 与检测框。GT 轨迹 ID 仅用于回溯人工记录，不作为跨侧对象对应依据；检测记录采用能够区分原始记录的独立身份，不依赖可能重复的检测 ID。不同帧不能因坐标相近而发生连接。

几何处理沿用第 1.3 节的统一约定：$Q=1000$、半开整数矩形、默认不裁剪、不额外去重或 NMS、不按框间 IoU 筛选。检测分数保留为元数据，不预设它一定是统一的 $0$–$1$ 概率。需要置信度阈值实验时，另建明确命名的版本，不覆盖主版本。

对每帧的两侧矩形施加相同平移，依据实际框范围隔离不同帧，保留组内 Area 与 IoU。发布前核对序列与帧数、有效 GT 和检测框数、筛选数量、分数范围以及空侧情况，并检查分组隔离与局部交叠关系。

### 2.4 构建后数据集的形态与使用

发布形态与 DocLayNet 一致：**可直接加载的 $R_1,R_2$、分组信息和必要来源元数据**。区别在于，一个语义分组表示某个序列中的一帧，左侧是有效行人 GT，右侧是官方检测框。

发布版本已经完成 GT—检测数据的整理与坐标处理。下载后不需要重新运行检测器、不需要重新解析原始视频标注，也不需要下载视频帧才能执行几何实验；只需固定版本并加载两侧关系。

可以选取完整帧构造规模实验，或直接使用全量训练帧实例。两侧必须使用相同的帧集合；若需要嵌套规模版本，应按固定场景顺序逐帧加入，不独立抽取左右框，也不复制矩形扩大规模。轨迹和分数信息只承担来源追溯或明确声明的分层分析用途，不改变主版本的连接语义。

该数据的发布说明须保留官方来源、原始许可与派生处理规则，并区分“输入已经构建”和“采样算法已经预处理”。性能比较中的枚举基线也应利用同帧分组，不能故意枚举跨帧无意义的组合。

## 3. COCO：COCO 2017 与 Sama-COCO 标注对照

### 3.1 数据集简要介绍

COCO 是通用对象检测与实例分割数据集。Sama-COCO 使用 COCO 2017 图像，提供重新整理的对象框和分割标注。两者使用相同的训练与验证图像划分，分别包含 118,287 张和 5,000 张图像，实际对象类别为 80 类。[^coco]

Sama 的标注过程以预载的 COCO 标注为基础，允许修改、保留、删除和补充记录，其变化涉及轮廓精细化、crowd 拆分与小对象处理。因此，这组数据属于**标注版本或标注方案对照**，不描述为完全独立的重复人工标注。[^sama]

本实验只关注矩形框，不使用分割轮廓作为采样对象。共同图像数量与原始标注总量只是源数据背景，最终规模以身份核验、非 crowd 筛选和几何检查后的结果为准。

### 3.2 研究中的使用方式与实际意义

**实验单位是“共同图像身份＋统一类别”。** $R_1$ 使用 COCO 2017 的非 crowd 有效实例框，$R_2$ 使用 Sama-COCO 中同图像、同类别的非 crowd 有效实例框。主版本两侧均排除 `iscrowd=1` 的记录。

**VOSMA-Area 的意义：共同矩形范围导向的版本核验。** 交集面积较大的跨版本框对获得更多抽样机会，用于核验较大共同图像范围内的候选对象关系。这里研究的是矩形交叠，不是对象真实像素范围或分割轮廓的共同覆盖。

**VOSMA-IoU 的意义：对象框相对几何一致性导向的版本核验。** 高 IoU 框对更容易被抽到，可用于检查对象位置和尺度相近的跨版本候选对应。不同版本的 annotation ID 不构成真实对应关系，采样也不代替实例匹配。

同类别、非 crowd 的限定使几何比较更明确，但也排除了跨类别分歧，并不能完整覆盖 crowd 拆分带来的变化。标注规则不同也可能产生版本差异，因此不能把几何不一致一律解释为标注错误。轮廓明显变化而外接框变化很小的情况，同样不在本实验的轮廓评价范围内。[^sama]

### 3.3 构建的基本方法与流程

整体流程为：**固定两套原始标注 → 核验共同图像与类别 → 筛选非 crowd 框 → 统一几何表示 → 按图像及类别隔离 → 核验并发布**。

先依据可核验的图像身份建立两侧对照，检查文件身份和图像尺寸，再建立明确的类别映射。不默认双方 image ID、annotation ID 或类别数组位置相同。图像缺失、身份冲突和图像存在但没有有效框，应分别记录，不能混作同一种情况。

两侧独立排除 crowd 和无效几何，随后按照统一类别建立分组。共同图像中某个类别只在一侧保留框时，也记录相应空侧状态，不把两侧共有对象假装成已经匹配的实例集合。

矩形面积由最终端点计算，不直接使用可能表示分割面积的原始 `area` 字段。其余几何处理沿用第 1.3 节约定：$Q=1000$、半开整数矩形、不裁剪、不做匹配或交叠阈值筛选。每个“图像＋类别”组的两侧共同平移；同图像的不同类别也应隔离，以保证算法不会产生主版本不允许的跨类别连接。

发布前核对共同图像数、类别映射、非 crowd 框数、无效与空侧情况，并统计或抽查 bbox 变化、交集面积和 IoU 分布。需要确认最终矩形任务具有怎样的变化与交叠结构，不能仅凭分割标注总量增加就推定 bbox 实验更丰富。

### 3.4 构建后数据集的形态与使用

发布形态与前两组一致：**两侧运行矩形、语义分组与来源元数据**。一个分组对应同一图像中的同一类别，元数据保留原图身份、统一类别及两套标注的原始记录身份，但不保存未经确认的一对一匹配。

Hugging Face 上的版本已经完成跨来源配对、非 crowd 筛选、整数化及分组平移。下载后不需要重新处理分割轮廓或原始标注，也不依赖原图才能运行 VOSMA；直接使用同一对 $R_1,R_2$ 比较 Area 和 IoU 即可。

全量实验使用所有已隔离的图像类别组。按图像选择规模子集时，同一图像下的全部类别组一起选入，避免只挑交叠较多的类别或独立抽取两侧框。数据说明应明确其范围是“同类别、非 crowd 的框级对照”，不将结果扩展解释为全部 COCO—Sama 标注变化或分割质量评价。

与前两组一样，发布时保留来源、许可、构建规则、实际规模和固定版本标识。三套数据虽来自不同领域，但实验入口均为**加载固定版本的双关系矩形输入，再运行算法自身的预处理与采样**。

## 4. 肯尼亚建筑：Microsoft 原始建筑轮廓与 Google Open Buildings V3

### 4.1 数据集简要介绍

Microsoft 与 Google 均发布了从卫星影像中自动提取的建筑轮廓。本实验限定到肯尼亚，微软侧固定采用 `KenyaNigeriaBuildingFootprints` 官方国家级发布中的 `Kenya.geojsonl.zip`，不与后续全球版本混用。该文件的官方原始规模为 **14,748,685 条建筑多边形记录**，采用逐行 GeoJSON 格式，底层 Maxar 影像来自 2020—2021 年。该数量是源文件背景规模，不是区域筛选与几何处理后的最终框数。[^ms-kenya]

谷歌侧固定采用 **Google Open Buildings V3 的原始建筑多边形**，并选取同一肯尼亚范围。V3 覆盖肯尼亚，提供建筑轮廓、置信度和位置等信息；其推理于 2023 年 5 月开展，这一时间不代表所有建筑影像的拍摄日期。本组不使用建筑点数据或时序栅格替代多边形，也不从已经完成跨来源融合或去重的产品中倒拆两侧输入。[^google-buildings-v3]

两侧均为机器生成的建筑记录，不把其中一侧视为人工真值。本组以 **$N=|R_1|+|R_2|$ 达到千万量级**为构建目标，不以去重后的建筑实体数或连接结果数定义规模。微软原始单侧数量提供了规模依据，但谷歌肯尼亚记录数及两侧处理后的实际规模仍须统计，不能预先声称两侧分别都达到一千万条。

### 4.2 研究中的使用方式与实际意义

**实验范围是同一固定版本的肯尼亚全国区域，保留真实地理布局。** 将两侧建筑多边形投影到同一平面坐标系，再提取轴对齐外接矩形，定义：

$$
\begin{aligned}
R_1 &= \text{所选肯尼亚范围内的 Microsoft 有效建筑记录的外接矩形},\\
R_2 &= \text{同一范围内的 Google Open Buildings V3 有效建筑记录的外接矩形}.
\end{aligned}
$$

对应任务是**跨来源建筑记录的几何一致性抽样核验**。两侧均采用单位记录权，Area 与 IoU 使用完全相同的矩形输入；来源置信度和原多边形面积不作为额外记录权。输入阶段不执行建筑实体匹配，也不要求先找到一对一对应。

**VOSMA-Area 的意义：共同矩形范围导向的建筑候选核验。** 交集面积较大的跨来源框对获得更多抽样机会，可用于按绝对空间交叠贡献分配核验预算。这里的面积是指定投影下的矩形交集面积，不是原建筑多边形的交集面积，也不是去重后的真实建筑覆盖面积。

**VOSMA-IoU 的意义：相对几何一致性导向的建筑候选核验。** 高 IoU 框对更容易被抽到，可用于核验位置与尺度相近的跨来源建筑记录。高矩形 IoU 是候选对应的几何证据，不是同一建筑的身份判定或匹配概率；原轮廓不同的记录也可能具有相同外接矩形，建筑拆分、合并或位置偏移则可能使真实对应不呈现高 IoU。

本组同时承担千万量级真实输入上的时间、内存和采样吞吐量实验，补充前三组按图像场景隔离的输入结构。**输入规模大不等于正质量连接稠密**，实际交叠对数和交叠度仍须测量。两侧版本差异也不能直接解释为建筑变化或检测错误；零交叠关系没有采样概率，因此本实验不构成全面的漏检、变化检测或建筑匹配评价。

### 4.3 构建的基本方法与流程

整体流程为：**固定两侧原始版本与肯尼亚范围 → 下载原始轮廓 → 统一投影与区域筛选 → 提取外接矩形 → 定点整数化 → 核验并发布**。

首先固定微软国家级文件、Google V3 下载清单，以及肯尼亚区域边界文件的来源、版本和校验信息。谷歌侧下载覆盖目标范围的原始多边形分块，再按统一规则筛选；官方 V3 多边形按 S2 level 4 分块存储于 CSV，轮廓以 WKT 表示。下载清单须避免重复导入同一源文件，并核查目标范围是否完整覆盖，不能把下载缺失当作正常空区域。[^google-buildings-v3]

**本组使用地理坐标转换，不直接沿用第 1.3 节的像素坐标解释。** 两侧共同采用一个覆盖肯尼亚、单位为米的 Lambert Azimuthal Equal Area（LAEA）等积投影，投影中心、基准、完整坐标参考系定义、经纬度轴序和转换软件版本在构建时固定并随版本发布。区域边界也转换到同一坐标系，不按来源、下载块或规模子集分别选择投影或归一化。必须先转换原始多边形，再提取外接矩形，不能先在经纬度空间取框后只投影四个角。等积投影也不意味着外接矩形与原轮廓具有相同面积或 IoU。[^buildings-projection]

区域选择采用共同规则：在上述投影平面内，以原始轮廓的质心是否位于固定肯尼亚边界内部或边界上决定保留；保留后使用完整轮廓，不沿国家边界裁剪。质心计算与边界包含判定的实现随构建版本记录，不直接混用两侧来源字段中可能按不同方法计算的中心点。边界附近因两侧轮廓不同而只保留一侧的情况属于输入范围的边界效应，不能通过跨侧匹配补齐或修正。

每条有效源记录生成一个轴对齐外接矩形；若原记录为 `MultiPolygon`，对其整体取框，不拆成多条记录扩大规模。端点按第 1.3 节的舍入规则处理：采用公共尺度 $Q=1000$，乘以 $Q$ 后按最近整数、居中取偶数得到半开整数矩形。这里 $Q=1000$ 表示米制坐标上的毫米网格，不代表源数据具有毫米级定位精度。矩形面积由最终整数端点计算，不使用原始多边形面积字段替代。精确采样的对象是**投影、取框和量化后发布的矩形**。

区域选择之外，仅排除无法解析、空或无效的多边形、非有限坐标、投影失败，以及量化后退化的框，并分类记录数量；不静默修复异常几何。主版本不额外设置置信度阈值，谷歌原始产品自身的置信度范围为 $[0.65,1.0]$，因此“不额外筛选”不表示源产品没有筛选。[^google-buildings-schema] 保留来源身份不同但几何相同的记录，不做额外 NMS、几何去重、跨来源配准或 IoU 阈值筛选，也不删除没有交叠对象的框。不能先按原多边形相交与否过滤候选，因为原轮廓不相交时，其外接矩形仍可能相交。

**下载分块只是存储单元，不是需要隔离的语义场景。** 不像前三组的页面或帧，本组不能对各块分别平移隔离，也不能只连接相同分块编号内的记录。全部矩形保留同一平面中的真实相对位置；若构建或验证过程按块处理，应覆盖跨块关系，并避免同一源记录被重复计入。

发布前核对两侧原始与最终记录数、各类剔除数量、边界选择情况、坐标与面积范围，并在固定局部区域叠加查看原轮廓和最终矩形。统计或抽查无交叠记录比例、交叠度、交集面积及 IoU 分布；全量统计、局部实测和估计结果须分别标注。实际连接规模不能用 $|R_1||R_2|$ 或原始建筑总数替代，未完成构建前也不预填最终千万级规模。

### 4.4 构建后数据集的形态与使用

Hugging Face 上的主版本沿用前三组的发布形态：**可直接加载的 NumPy 双关系矩形数组、分组信息和必要来源元数据**。左侧为微软建筑外接矩形，右侧为 Google V3 建筑外接矩形，运行输入提供统一整数端点与单位权重。整个肯尼亚范围作为一个空间实例和语义组；下载块编号仅用于回溯或存储，不限制允许连接的记录对。

每条矩形保留能够唯一定位源记录的身份，例如来源、文件标识与文件内行号的组合，并保留原轮廓回溯信息、原始位置、可用置信度、区域边界版本、投影定义和量化规则。不把两侧记录编号或位置编码当作跨来源对应关系。大规模数组可按固定清单分片存储，但须提供可重建完整 $R_1,R_2$ 的顺序和加载说明；发布内容不包含预先枚举的相交框对、建筑匹配或 VOSMA 索引。

使用时固定版本，直接加载两侧矩形，由 VOSMA-Area 与 VOSMA-IoU 各自执行预处理和采样，**无须重新下载原始建筑文件、解析多边形或执行坐标投影，也不依赖卫星影像才能运行几何实验**。原轮廓与影像仅用于另外声明的核验，不参与主版本运行输入的在线生成。

小规模验证与嵌套规模实验按预先固定的共同地理子区域选择两侧记录，沿用全量版本的投影、质心选择和量化规则，保留入选记录的完整矩形。不能独立抽取左右框、只挑已有高 IoU 对应的建筑，或复制记录扩大规模。全量实验按整个输入的质量采样；各分块等量采样后合并，不等于全局目标分布。枚举基线应利用真实空间坐标和合理空间索引，不以全笛卡尔积暴力比较作为唯一基线。

发布时补充实际 $|R_1|$、$|R_2|$、$N$、文件大小、下载地址、构建规则与固定校验信息，并保留两侧数据和边界文件的来源与许可。上述微软国家级文件标注 ODbL；Google 原始数据允许选择 CC BY 4.0 或 ODbL，派生发布须明确所采用的许可及相应署名与处理说明，不能借用另一微软产品的许可替代本文件条款。[^ms-kenya][^google-buildings-v3] 原始下载、区域筛选、投影和矩形化属于一次性数据制备，算法自身的索引与采样结构仍须在实验中构建并计时。运行时检查面积、累计质量及其他中间量的数值范围，并测量实际峰值内存，不以端点可存储或矩形数组较小推定完整算法一定可运行。
